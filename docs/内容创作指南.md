# 山河局 · 内容创作指南

目标：以后加故事，主要改内容；以后加新玩法，才改程序。当前格式版本为 1，游戏存档版本为 2。

## 一、最容易的扩写方式

1. 在游戏中进入「内容工坊 → 扩写编辑器」。
2. 下载示例内容包，或直接修改编辑框中的内容。
3. 修改事件 ID、标题、正文、选项、条件与效果。
4. 点击「仅校验」，确认无重复 ID、缺失引用、错误字段或无退路选项。
5. 点击「校验并导入」。符合条件后，新故事便会进入当前局的调度池。

浏览器导入不需要编译，也不需要安装开发工具。内容包保存在当前浏览器；下载存档时会一并打包。重开保留导入内容。若只想改正文而不改 ID，需改项目源文件；导入功能不允许覆盖已有基础事件，避免当前存档的分支被悄悄换掉。

完整事件库可从工坊导出，或查看 `content/full-content.json`。这份文件是阅读与迁移用的全库底稿，不能原样再次导入同一游戏，因为 ID 都已经存在。

## 二、内容包的最小格式

```json
{
  "formatVersion": 1,
  "name": "我写的第一卷",
  "events": [
    {
      "id": "my-tea-stall",
      "kind": "random",
      "routes": ["trade", "scholar"],
      "title": "茶摊的新账本",
      "text": "茶摊老板想学记账，又怕年纪太大记不住。他把一把长短不齐的算筹推到你面前。",
      "cooldown": 8,
      "choices": [
        {
          "label": "教他用每日进出两栏记账",
          "text": "老板照着记了一页，终于发现少掉的钱不是被人偷去，而是自己忘算了茶炭。",
          "effects": {"routes.trade": 3, "stats.business": 1}
        },
        {
          "label": "替他画一套简单的记号",
          "text": "他不必先学会全部的字，也能记住今天到底做成了什么。",
          "effects": {"routes.scholar": 3, "morality": 2}
        }
      ]
    }
  ]
}
```

JSON 中不能写注释、尾逗号、单引号或函数。正文需要换行时写 `\n`。程序只显示文本，不执行 HTML 或脚本。

## 三、事件字段

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| id | 全库唯一，字母开头，仅小写字母数字连字符，2—80 字符 | my-tea-stall |
| kind | random 随机；story 连续主线；followup 只由后续调度 | story |
| routes | 相关道路 ID 数组；all 表示公共事件 | ["martial","official"] |
| title | 玩家看到的标题 | 武道二 · 断剑门人 |
| text | 场景正文，写清谁在场、什么冲突、为什么由玩家定夺 | 一段完整场景 |
| choices | 2—6 个选项 | 见下文 |
| once | true 表示一局只完成一次 | true |
| cooldown | 距上次完成至少几天才可再次出现 | 8 |
| weight | 随机事件基础权重，正数；不写为 1 | 2 |
| order | 主线调度排序，越小越优先；不保证立即触发 | 12 |
| when | 事件进入候选池的条件 | 见条件章节 |

主线建议同时写 `kind: "story"` 和 `once: true`。余波建议写 `kind: "followup"` 与 `once: true`，由 `delay` 或 `next` 引用。

随机事件每次调度会避开最近 12 个已完成事件；候选池耗尽时可回到满足冷却的全部随机事件。不要用它替代一次性设置。

## 四、选项字段

每个选项至少写 `label` 与 `text`。没有判定时，`text` 是选择后的结果。所有选项都可以有 `effects`、`cost`、`requires`、`next` 或 `delay`。

| 字段 | 含义 |
| --- | --- |
| label | 按钮上的行动；清楚说出玩家准备做什么 |
| text | 无判定时的结果；应确实回应这个行动 |
| effects | 选择后无条件生效的变化，判定失败也生效 |
| cost | 选择前检查并扣除的资源，值必须是非负数 |
| requires | 选项可用条件；不满足时会显示为禁用 |
| check | 属性判定，含 stat、difficulty |
| success | 成功后的 text、effects、next、delay |
| failure | 失败后的 text、effects、next、delay |
| next | 完成后立即打开另一个事件 ID，不额外消耗行动 |
| delay | 完成后若干天排入一个事件，含 id、days |

必须至少有一个选项不带 `requires` 和 `cost`。该选项可以承担其他代价，但不能要求玩家拥有可能不存在的银两、物品或先前分支；否则事件可能把游戏锁死。校验器会检查这条规则。

带判定的例子：

```json
{
  "label": "从账册里寻找重复抵押",
  "effects": {"routes.trade": 3},
  "check": {"stat": "business", "difficulty": 48},
  "success": {
    "text": "两张同号仓单的日期终于对上，你拿到了能要求重新结算的依据。",
    "effects": {"silver": 30, "stats.business": 1}
  },
  "failure": {
    "text": "你仍缺一份原始存根，未能指认是谁做手脚。至少已经知道下一步该找什么。",
    "effects": {"stats.insight": 1}
  }
}
```

失败不应只写“你失败了”。失败也可以留下信息、改变代价、引向另一种解法。基础效果与结果效果按顺序叠加；同一字段两处各加 2，实际就是加 4。

基础成功概率：`0.5 + (属性 - 难度) / 85 + (气运 - 40) / 600`，先限制在12%—94%。同属性修习的最高熟练每25点再增加1.5个百分点，最终上限97%。界面显示已包含助益的当前成功率。不要在正文里承诺尚未实现的装备倍率。

## 五、数值与效果路径

普通数值效果用增量。`"silver": 20` 为增加 20 两，`"silver": -10` 为减少 10 两。`cost` 中一律填正数，例如 `"cost": {"silver": 20}`。

| 字段 | 范围及作用 |
| --- | --- |
| silver | 银两，最低 0 |
| health | 健康，0—100；归零获救并损失四成现银 |
| renown | 声望，可为负，当前用于角色显示与内容条件 |
| heat | 恶名，0—100；45 以上触发周期打点成本，每天自然下降 2 |
| morality | 善恶，-100—100；为行为记录与条件，不替玩家定义身份 |
| stats.xxx | 八项属性，0—100 |
| routes.xxx | 道路阅历，最低 0，不设满级封顶 |
| factions.xxx | 玩家与势力的关系，-100—100 |
| relations.xxx | 个人信任，-100—100 |
| inventory.xxx | 物品数量，最低 0，可自定义小写物品 ID |
| flags.xxx | 剧情标记，直接设置为给定布尔、字符串或数值，不是累加 |

属性 ID：`martial` 武艺、`business` 商才、`learning` 学识、`strategy` 谋略、`charm` 交际、`insight` 洞察、`constitution` 根骨、`luck` 气运。

道路 ID：`martial` 武道、`trade` 行商、`official` 官路、`outlaw` 绿林、`scholar` 学问、`medicine` 医道。属性 `business` 与道路 `trade` 不同；属性 `learning` 同时能帮助官路与学问。

势力 ID：`court` 州府、`censor` 巡按、`guild` 商盟、`canal` 漕帮、`sword` 剑会、`escort` 镖局、`blackflag` 连寨、`shadow` 夜渡社、`academy` 书院、`healers` 济世堂、`army` 边军、`smith` 百工盟。

人物 ID 可查 `content/world.js` 中的 people；例如 `shen` 沈砚、`tang` 唐绮、`yan` 燕停云、`luo` 罗照夜、`wen` 温见素。新增人物应先加入世界数据，再在事件引用。

货物 ID：`grain` 粮、`salt` 盐、`tea` 茶、`silk` 绸、`medicine` 药、`iron` 铁、`porcelain` 瓷器、`cloth` 棉布、`gauze` 纱布、`paper` 纸。货物同时存在 inventory 中；产业原料和未提产出另存于产业仓。药材与可使用伤药合并计数，消耗一个 medicine 可恢复20健康。

新增可用条件旗标：`household` 当前有配偶，`has_children` 当前家主有子女，`owns_assets` 当前有产业。它们由系统维护，适合限定家事与经营剧情，不应由普通选项随意改写。`systemScene: true` 是运输、产业和家族动态风波的保留标记，普通扩写不使用它。

旗标推荐加个人或篇章前缀，例如 `flags.my_orchard_helped`，避免无意重用别人的状态。ID 不能使用 JavaScript 原型相关名称，内容包也不能包含任意状态写入。

## 六、条件格式

`when` 控制事件能否触发；`requires` 控制一个选项是否可选。所有写入的条件为“同时满足”。`cities` 和 `tags` 数组内部为“至少匹配一个”。

```json
{
  "when": {
    "min": {"day": 6, "routes.trade": 18, "inventory.evidence": 1},
    "max": {"heat": 40},
    "cities": ["yunzhou", "donghai"],
    "seen": ["my-tea-stall"],
    "notSeen": ["my-alternative-ending"],
    "flags": {"my_orchard_helped": true}
  }
}
```

- `min` / `max`：数字阈值。可使用上面的数值路径，以及只用于条件的 `day` 和 `energy`。
- `cities`：所在城市 ID 至少一个匹配。
- `tags`：所在城市标签至少一个匹配，例如 `port`、`forest`、`court`、`academy`、`herb`、`frontier`、`military`、`sect`、`mine`、`sea`、`farm`。
- `seen`：列出的事件全都已完成。仅打开未选择不算完成。
- `notSeen`：列出的事件全都尚未完成。
- `flags`：标记值严格相等。注意未设置的标记不等于 false；若需 false 分支，先明确写入 false。
- `route`：当前主道路 ID；需要严格围绕主道的篇章才使用。常规主线更建议检查阅历，给玩家保留跨路空间。

城市 ID 与中文对照：lanzhou 澜州、heyang 河阳、jingdu 京畿、linchuan 临川、beiting 北庭、shuofang 朔方、shazhou 沙州、yumen 玉门、qinghe 青河、songshan 松山、yaogu 药谷、nanpu 南浦、yunzhou 云州、donghai 东海、mingzhou 明州、tieshan 铁山。

## 七、连续、分支与延迟回响

连续主线：第二章的 `when.seen` 指向第一章；加阅历与地点门槛，便能形成既有成长又有行旅的故事。各道路首章门槛为 8，后续为 18、32、48；这是当前内容约定，不是引擎硬限制。

互斥分支：第一章选择 A 时写 `"flags.my_choice": "a"`，选择 B 时写 `"flags.my_choice": "b"`；后续分别检查相等值。务必保留未进入某分支时仍能完成当前事件的选项。

延迟回响：

```json
{
  "label": "留下可核对的借据",
  "text": "对方收好借据，答应三天后回信。",
  "effects": {"flags.my_loan": true},
  "delay": {"id": "my-loan-reply", "days": 3}
}
```

同一个内容包中应同时含 `my-loan-reply`，其 kind 为 followup。到期的余波优先于普通事件，休息过夜或下一次事件调度时打开，不额外扣行动。排入 delay / next 的事件按明确剧情引用直接打开，不重新检查它的 when；需要按分支选择不同后续，应在选项里引用不同事件，而非依赖 followup 的 when。

followup 即使定义了多个未履行条件，也不能拿来代替安全出口。连续后续也必须至少有一个无门槛选项。

当前“延迟”是游戏日，不是现实时间。关掉网页不会自动过日或跑产业，不需要定时在线。

## 八、调度怎样偏向主要道路

玩家进行相关行程时，系统先处理到期余波。若无余波，符合条件的相关主线有 52% 机会优先进入，按 order 排序。否则从随机事件池抽取。

随机事件权重为：基础 weight × 道路系数。与本次行动道路相关为 4 倍；否则与当前主道路相关为 3 倍；公共事件 1.5 倍；其他道路 0.75 倍。多道路事件同时关联多个路径，因此天然能成为交叉节点。

这些系数代表相对权重，不是“固定 40% / 30%”。实际概率取决于当时可触发的内容数量和条件。想控制比例，应补齐各类事件池并观察游玩结果，不能只改一条概率常量。

为免等随机，手札里的可用主线也可主动推进，消耗 1 行动。内容作者不需要给每条主线强制连续 next，玩家仍可在章节间经营、修习或换城。

## 九、写一段有后果的事件

建议顺序：先确定共同事实，再写角色利益，再给玩家能够理解的行动，最后写选择实际改变了什么。

一个好选项不必一次解决全部问题。例如保住证人的性命、留下可核对的副本、争取三天期限，都比直接让玩家“改变天下”更容易产生可信后续。与大势力的关系变化宜为 2—8 点，重要终章再给 10—15 点。小事件若反复增加 80 点，其他门槛很快失去意义。

普通事件正文建议 80—180 字，2—3 个选择，每个结果 30—100 字。重要篇章可更长，但要在开头说清发生的事。每个选项都要有能够解释的代价或取舍，不必总是“善 / 恶 / 离开”三件套。

给其他道路留入口，可以通过商契、证据、病录、工钱、药源、通行、署名、身份之一连接。不要为跨路而跨路：山寨与医者发生联系，最好因为山民确实需要药，而不是两个人恰好同时站在客栈门口。

避免只换地名批量复制事件。新增事件应该至少改变一个实际问题、行动方式、人物立场或后果结构。

## 十、永久加入项目

源文件采用很薄的 JavaScript 包装以兼容双击 index.html 的本地游玩：

- `content/world.js`：出身、天赋、属性、道路、城市、势力、人物、货物、产业与技能。
- `content/encounters.js`：随机事件，E 是默认 kind=random 的便捷构造器。
- `content/chapters.js`：主线与余波，S / F 分别对应 story / followup。
- `engine.js`：纯状态与规则，不含页面排版。
- `game.js`：页面渲染、交互、存档、导入导出。

在 events 数组里可以直接插入标准 JSON 事件对象，不必使用 E / S / F。包装器只是减少重复，不是另一个格式。

完成修改后：

```text
node --test tests/*.test.js
node build.js
node server.js
```

浏览器访问控制台显示的本地地址。也可以直接打开根目录 index.html。构建会更新 `docs/剧情文本全卷.md`、`docs/事件索引.md`、`content/full-content.json` 与 dist，不能直接改生成文件后期待引擎跟着改变。

新增世界实体时，请同步考虑关联：城市要有双向 links 与全部十种 goods 系数；人物要有存在的 city / faction，婚配还需 gender、age、social、married 与 acceptsConcubine 等字段。产业规则或全新道路需要检查引擎与界面支持。纯内容包当前只扩展事件，不能直接添加城市、道路或系统代码。

## 十一、交稿检查

1. ID 唯一；所有 next、delay、seen、notSeen 指向现有或本包事件。
2. 所有事件至少有一个无门槛选项。
3. 主线有 once；重复事件有合适 cooldown。
4. 需要资源的选择写在 cost，而不是只在结果里扣钱。
5. 成功与失败都有正文；基础效果叠加符合预期。
6. 标签、城市、人物、势力和属性 ID 使用正确。
7. 普通 effects 仍不直接创建婚姻、子女、NPC迁徙与新建筑；这些由专用系统处理。正文不能声称一个普通数值效果已经完成了未调用的系统行动，或授予尚未实现的官职实权。
8. 真正试玩该事件，检查边界状态：零银、低健康、无物品、改道、不同先前选择。

故事可以很庞大，规则最好一直清楚。
